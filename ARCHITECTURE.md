# المعمارية الأمنية والتحصين السيبراني لتطبيق "أبوي وأمي" (My Parents Call)
## Security Architecture & Threat Model Specification

تطبيق **"أبوي وأمي"** مصمم خصيصاً كمنظومة اتصال عائلية خاصة ومغلقة (Private Zero-Trust Family VoIP System)، توفر تجربة مستخدم فائقة البساطة لكبار السن مع تطبيق أعلى معايير الحماية السيبرانية العسكرية لمنع التنصت أو هجمات الرجل في المنتصف (Man-in-the-Middle - MITM) أو محاولات الاختراق بعد الرفع والاستضافة.

---

## 1. نموذج التهديد (Threat Model & Mitigations)

| ناقل التهديد (Threat Vector) | سيناريو الهجوم | آلية الدفاع والتحصين المطبقة |
| :--- | :--- | :--- |
| **MITM على خادم الإشارات (Signaling MITM)** | اعتراض رسائل SDP وتبادل المفاتيح عبر الشبكة أو مزود الخدمة. | فرض بروتوكول TLS 1.3 حصرياً مع HSTS Preload، تشغيل WebSockets عبر WSS فقط، ورفض أي اتصال غير مشفر. |
| **التنصت على الصوت والفيديو (Media Eavesdropping)** | التقاط حزم RTP الصوتية والمرئية أثناء انتقالها في مسار P2P أو عبر الخادم الوسيط. | إجبارية بروتوكول **DTLS-SRTP** مع تشفير AES-GCM لتدفقات الميديا. لا يمر الصوت والفيديو عبر خادم الإشارات إطلاقاً. |
| **انتحال الهوية والدخول غير المصرح به (Unauthorized Access)** | محاولة طرف ثالث تخمين الرابط أو الاتصال بالخادم لإزعاج الوالدين أو التجسس. | مصادقة صارمة متعددة الطبقات: تحقق أولي عبر PIN سري عائلي مشفر بـ bcrypt، ثم إصدار رمز JWT قصير الأجل (15 دقيقة) مشفر بـ HMAC-SHA256، وإلزامية إرفاقه في مصافحة WebSocket (Handshake). |
| **استغلال سيرفر الترحيل (TURN Server Abuse)** | استغلال سيرفر TURN المجاني لتمرير بيانات غير مشروعة أو استنزاف الباندويث. | توليد بيانات اعتماد مؤقتة ديناميكياً (**Ephemeral Credentials**) بصلاحية زمنية قصيرة (30 دقيقة) باستخدام خوارزمية HMAC-SHA1 المتوافقة مع معيار RFC 5766 / CoTURN REST API. |
| **هجمات حجب الخدمة والفيضان (DoS / Signaling Flooding)** | إرسال آلاف الطلبات أو رسائل ICE Candidate لإسقاط الخادم. | تطبيق Rate Limiting متعدد المستويات (على طلبات HTTP وعلى أحداث Socket.io بشكل مستقل)، مع تقييد الحجم الأقصى للحزم لمنع تجاوز الذاكرة. |
| **حقن البيانات والمدخلات الخبيثة (Injection & Malformed SDP)** | إرسال حزم SDP أو ICE معدلة للتسبب في ثغرات Buffer Overflow أو Prototype Pollution. | تدقيق صارم وصارم للمدخلات (Strict Schema Validation) باستخدام مكتبة **Zod** على جميع كائنات SDP و ICE Candidates قبل معالجتها. |
| **تجاوز نطاق المتصفح (Cross-Origin Hijacking)** | تضمين الموقع في IFrame أو استدعاء الـ API من نطاقات خارجية. | سياسة CORS صارمة جداً، بالإضافة إلى ترويسات أمان Helmet (بما في ذلك X-Frame-Options: DENY و CSP صارم و HSTS). |

## 3. طبقات الحماية البرمجية والخادم (Defense-in-Depth Architecture)

### 3.1 طبقة خادم الإشارات (Signaling Layer)
- **Node.js (ES Modules)** لسرعة الأداء وعدم حظر الخيوط (Non-blocking I/O).
- **Socket.io مع WSS**: الاتصال محمي بطبقة TLS مع مصادقة معترضة في الـ Middleware قبل قبول أي Socket Connection.
- **إدارة الحضور المعزولة (Isolated Family Room)**:
  - لا يمكن لأي مستخدم الاتصال بمستخدمين خارج شبكته العائلية المعرفة.
  - الأسماء المسموحة: `father` (الوالد)، `mother` (الوالدة)، `child` (الابن/الابنة).
  - لا توجد غرف عامة مفتوحة للجمهور.

### 3.2 طبقة التشفير المتبادل للوسائط (Media Layer DTLS-SRTP)
- بروتوكول WebRTC يفرض تشفير **DTLS** لمصافحة المفاتيح وتشفير **SRTP** لنقل حزم الصوت والفيديو.
- يتم توليد أزواج مفاتيح تشفير عشوائية وجديدة تماماً لكل جلسة اتصال منفردة في ذاكرة المتصفح.
- لا يستطيع خادم الإشارات ولا حتى مزود خدمة الإنترنت (ISP) فك تشفير محتوى الصوت والصورة.

### 3.3 حماية سيرفر الترحيل (TURN Protection)
- استخدام معيار **Coturn REST API / Ephemeral Auth**:
  ```text
  username = expiry_timestamp : user_identifier
  password = base64( HMAC-SHA1( username, TURN_STATIC_AUTH_SECRET ) )
  ```
- هذا يضمن أن بيانات الاعتماد لا يمكن إعادة استخدامها بعد انتهاء مدتها (Replay Attack Resistant)، مما يمنع سرقة خادم الترحيل.

## 4. إرشادات ما بعد الرفع لضمان انعدام الاختراق
1. **عزل المنافذ (Firewall UFW)**: إغلاق جميع المنافذ ما عدا (80, 443, 3478 UDP/TCP, ونطاق UDP لمنافذ الوسائط 49152-65535).
2. **الترخيص التلقائي لـ SSL**: استخدام Let's Encrypt مع التجديد التلقائي عبر Certbot.
3. **عدم تضمين أسرار في الكود**: حفظ جميع المفاتيح في ملف `.env` بصلاحيات قراءة مشددة (`chmod 600 .env`).
